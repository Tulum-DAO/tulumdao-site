The Lethal Trifecta

How to find the three capabilities that turn an AI agent’s helpfulness into an exploitable path—and how to break the circuit.

01 — WHY IT MATTERS

Three capabilities. One dangerous combination.

In June 2025, Simon Willison named the lethal trifecta: private data, untrusted content, and external communication. A system with all three can carry an attacker’s instruction from something it reads to something it can reveal.

Private data and untrusted content without a route out is contained. Untrusted content and egress without secrets has little to steal. Together, all three complete the circuit.
02 — THE THREE LEGS

Look beyond obvious permissions.

Private data

Email, files, databases, credentials, API keys, environment variables, internal documentation, chat history, memory stores, transcripts, inboxes, and tool output can all be sensitive. Access may arrive through a mounted directory, inherited environment, shared state, or a tool that returns more than the task needs.

Untrusted content

Anything an outsider can influence and an agent may read: web pages, incoming mail, documents, search results, tool and API output, images, issues, pull requests, package documentation, calendar invites, messages, and tool descriptions.

External communication

HTTP requests, email, messages, public posts, URL parameters, rendered links or images, DNS, and another agent with egress are all routes outward. Indirect reach counts: if one agent can ask another agent to send, the chain has egress.

03 — THE CIRCUIT

Two legs can be useful. Three need a design decision.

Read outside content → injected instruction → read private data → ordinary-looking outward action. The usual solution is not to stop reading; it is to keep secrets out of the reader’s reach and make outward actions narrow, allow-listed, or approved.
04 — ILLUSTRATION, NOT A REAL INCIDENT

A believable failure chain.

A support agent reads inbound tickets. It can consult a CRM export and uses a service credential from its environment. It also posts a summary to a webhook. A ticket includes instructions disguised as troubleshooting notes. The agent follows them, gathers data it was not asked to use, and places it in an ordinary-looking outbound request.

The fix is not a better warning in the ticket. Separate the ticket reader from customer records, keep credentials behind a capability that does not reveal them, and restrict or require approval for the outbound route.

05 — THE AUDIT PROMPT

Ask your main agent to map the exposure.

This prompt is deliberately read-only. It inventories direct access and reach through other agents; it does not attempt an injection or send data.

You are auditing the AI agents I run for the “lethal trifecta”: an agent is exploitable by prompt injection when it has all three of (1) access to private data, (2) exposure to untrusted content, and (3) a way to communicate outward.

Do this READ-ONLY. Do not change configuration, send anything, test exfiltration, or try an injection. If an action would be required, stop and ask me.

1. Inventory every agent you can see: yourself, sub-agents, agents you can message, and agents whose output you consume. For each, list tools, integrations, file/network access, and credentials or environment variables it can read.
2. For each agent, mark the three legs with evidence: private data, untrusted content, and outward communication. Count reach through agents and tools.
3. Flag every agent or chain with all three. Give the shortest realistic two- or three-sentence path: where injected text enters, what it could access, and how it could leave.
4. For each flag, recommend the one cheapest leg to break: keep the secret host-side, allow-list egress, split reader from holder, or require approval before outbound action.
5. Report a table: Agent | Leg 1 evidence | Leg 2 evidence | Leg 3 evidence | Trifecta? | Cheapest leg to break. Then list flagged chains and unknowns plainly.

A good answer distinguishes evidence from guesses, includes indirect chains, and names uncertainty instead of filling it with assumptions.

06 — BREAK THE CIRCUIT

Remove a leg where it costs least.

  • Keep secrets host-side; provide narrow capabilities rather than raw credentials.
  • Give agents only the files, records, and tools needed for the task.
  • Allow-list destinations and methods; make egress typed or approval-gated.
  • Separate agents that read outside content from agents that hold sensitive data.
  • Review chains, not only individual agents: delegation can reconnect a leg you thought was absent.
